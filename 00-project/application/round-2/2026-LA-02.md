# League of Legends Match Data Warehouse

## My interpretation of the brief
This project focuses on building an end-to-end data warehouse system that extracts raw match performance data from the official Riot Games API and transforms it into a structured dimensional model (Star or Snowflake schema)[cite: 7]. The primary challenge lies in staging raw data, designing an scalable ETL/ELT pipeline with incremental loading capabilities for hundreds of thousands of matches, and optimizing complex analytical SQL queries for historical player, champion, and patch trends.

## Why I am a good fit for this project
I am interested in data engineering, data warehousing, and backend data pipelines. Working with a large, highly structured dataset like match statistics provides a great opportunity to gain hands-on experience with production-grade database concepts. Designing a dimensional model that handles millions of fact records while remaining responsive to complex analytical queries perfectly aligns with my technical goals in database systems.

## Relevant experience and background
- **Relational Databases & SQL:** Strong grasp of relational schema design, third normal form (3NF), complex multi-table joins, CTEs, and writing analytical queries.
- **Data & API Handling:** Experience building scripts to interact with RESTful APIs, handling rate limits, parsing structured JSON payloads, and managing staging environments.
- **Development Tools:** Comfortable using Git version control, SQL Server / Oracle Database tools, and organizing software engineering projects in Visual Studio.

## Proposed approach
I will start by setting up a staging layer to store raw JSON match data fetched via Python/C# scripts from the Riot Games API, preserving source data traceability. Next, I will evaluate Star vs. Snowflake schemas to design a clear dimensional model centered on player-match performance facts linked to time, champion, role, and patch dimensions. I will build an ETL/ELT process for data cleaning, standardization, and incremental loading, followed by complex analytical queries and index execution plan optimization.

## Initial plan
1. Define data warehouse requirements, facts/dimensions granularity, and document schema trade-offs.
2. Develop automated scripts to fetch raw match data from the Riot Games API into a staging database.
3. Build and test the ETL/ELT pipeline supporting incremental loads into the dimensional warehouse.
4. Implement complex analytical SQL queries for champion win-rates, patch comparisons, and player trends.
5. Execute performance measurements, analyze query execution plans, apply indexing/partitioning, and write final documentation.
